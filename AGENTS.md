# AGENTS.md

## Project Overview

SmartEat Printer Agent is an Electron desktop app with a Vue 3/Vite frontend and a Node/Electron main process.

The app discovers local network printers, stores printer configuration in `settings.json`, exposes a local HTTP agent on port `8989`, and sends print jobs to configured printers.

## Stack

- Electron main process: `index.js`
- Frontend: Vue 3 single page app in `src/`
- Build tooling: Vite, Tailwind CSS, Electron Builder
- Printer protocols currently present:
  - Bonjour/mDNS discovery
  - ESC/POS over TCP port `9100`
  - IPP on port `631`
  - Epson ePOS HTTP on port `80`
  - LPR placeholder path on port `515`

## Useful Commands

Use `npm.cmd` on Windows if PowerShell blocks `npm.ps1`.

```powershell
npm.cmd install
npm.cmd run build
npx.cmd vite
npx.cmd electron .
```

There is currently no real test suite. `npm test` intentionally exits with an error in `package.json`.

## Important Files

- `index.js`: Electron main process, printer discovery, local Express API, print functions, saved settings.
- `src/views/PrintersView.vue`: printer discovery UI, protocol/ticket toggles, test print button.
- `src/views/PrintingView.vue`: polling flow for print jobs.
- `src/views/AccountView.vue`: SmartEat login/session UI.
- `src/config.json`: environment endpoints.
- `settings.json`: local runtime settings generated by `electron-store`. Treat as local/private data.

## Local Data And Safety

Do not commit or expose real tokens from `settings.json`.

The current app stores user session data and printer configuration through `electron-store` with `cwd` set to the app base directory. In development, this means `settings.json` can exist at the project root and may contain local IPs and auth tokens.

## Known Issues To Watch

- `src/views/PrintingView.vue` invokes `ipcRenderer.invoke("print-job", job)`, but no matching `ipcMain.handle("print-job")` currently exists in `index.js`.
- `/print` in `index.js` responds with a message referencing `ip`, but `ip` is not defined in that scope.
- `printLpr()` is called in the test-printer flow for port `515`, but no `printLpr` function is currently defined.
- `PrintersView.vue` uses `this.printers` inside `<script setup>` in `savePrinterConfig()`. In Vue `<script setup>`, this should use `printers.value`.
- Several user-facing strings appear mojibake-encoded in the checked-in files. Preserve encoding carefully when editing.
- Electron is configured with `nodeIntegration: true` and `contextIsolation: false`. This is convenient for local hardware access but not ideal for a hardened production desktop app.

## Bluetooth Printing Direction

For Windows Bluetooth printing, prefer integrating with the Windows printer subsystem first:

1. Pair the Bluetooth printer in Windows.
2. Let Windows expose it as an installed printer/queue.
3. Use a Node/Electron printing path such as `pdf-to-printer`, PowerShell, or Windows spooler commands.

Direct Bluetooth serial/ESC-POS is possible for compatible thermal printers, but it requires identifying the COM port created by Windows after pairing and writing ESC/POS bytes to that serial port through a package such as `serialport`.

Keep the print routing abstraction protocol-based, for example:

- `network-escpos`
- `ipp`
- `epos-http`
- `windows-spooler`
- `bluetooth-serial`

This avoids mixing discovery, saved configuration, and transport-specific printing logic in one function.
